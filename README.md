# PAN-OS object cleanup

כלי לניתוח ולניקוי אובייקטים ב־Palo Alto Firewall או בקבוצת מכשירים ב־Panorama.
ברירת המחדל היא **הצגת תוכנית בלבד**: אין מחיקה ואין commit לפיירוול.

## התקנה

נבדק עם Python 3.12. ב־Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

ב־Linux או macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

בדוגמאות הבאות `python` הוא המפרש מתוך `.venv`. אפשר להחליף אותו בנתיב המלא
מהפקודות למעלה, בלי להפעיל את סביבת העבודה. הכלי משתמש ישירות ב־`pan-python`,
לקוח ה־XML API שבו משתמשת גם הספרייה `pan-os-python` שבגרסה הקודמת.

## ניסוי בלי פיירוול

```bash
python new_pa_cleanup.py --config tests/fixtures/lab.xml
python new_pa_cleanup.py --config tests/fixtures/lab.xml --plan-file lab.plan.json
```

קובץ הדוגמה הוא XML סינתטי שמייצג את `lab-2-create-all.txt`. במצב רגיל נמצאים
21 אובייקטים: 9 מועמדים למחיקה ו־12 נשמרים. שני האובייקטים `SRV-OLD01` ו־
`SRV-OLD02`, למשל, נמחקים רק אחרי הקבוצה `GRP-OLD` שמפנה אליהם.

הניתוח מבוסס על הפניות בשמות: `SRV-ADMIN` אינו נחשב בשימוש רק מפני שחוק מכיל
ישירות את כתובת ה־IP שלו. הכתובת המילולית בחוק אינה הפניה לאובייקט.

אפשר להשתמש ב־`--config` גם עם קונפיגורציה מיוצאת משלך. שמור אותה בשם שמסתיים
ב־`.local.xml`, כדי ש־Git יתעלם ממנה. קונפיגורציות עשויות להכיל מידע רגיש.
מצב זה לא מבצע חיבור למכשיר ואינו מאפשר `--apply` או `--commit`.

## ניתוח מול מכשיר

```bash
python new_pa_cleanup.py --host 192.168.56.10 --user admin --ca-bundle firewall-ca.pem
```

הסיסמה מתקבלת בהקלדה מוסתרת. לחלופין ניתן להגדיר `PAN_PASSWORD`, או להשתמש
ב־`PAN_API_KEY`; שם המשתמש יכול להינתן גם ב־`PAN_USER`. אין לשמור סודות בקוד,
בפקודות ששומרות היסטוריה או ב־GitHub.

אימות תעודת TLS פעיל, כולל בדיקת שם המארח. `--ca-bundle` מקבל קובץ PEM עם
תעודה/רשות אישורים שאימתת ושאתה סומך עליה. השתמש בשם מארח או כתובת שתואמים
לתעודה. אם התעודה מוכרת למאגר האמון של Python, אין צורך בפרמטר הזה.

ברירת המחדל היא `vsys1`. אפשר לבחור `--vsys vsys2`, או לבחור Panorama באמצעות
`--device-group LAB`. לפני כל ניתוח חי נוצר גיבוי של **candidate configuration**
בתיקיית `backups/`; כשל בכתיבת הגיבוי עוצר את הריצה.

## מחיקה בפועל

```bash
python new_pa_cleanup.py --host 192.168.56.10 --user admin --ca-bundle firewall-ca.pem --keep SRV-DC01 --apply
```

הכלי מציג את התוכנית ומבקש להקליד את היעד והאזור, למשל
`192.168.56.10/vsys1`. מיד לאחר האישור הוא קורא שוב את הקונפיגורציה; אם היא
השתנתה מאז הניתוח, הוא עוצר לפני מחיקה. `--keep NAME` ניתן לחזרה ומגן על כל
האובייקטים בשם הזה, וגם על התלויות שלהם. שם לא קיים נחשב שגיאה.

ללא `--commit`, המחיקות נשארות ב־candidate configuration. הפרמטר `--commit`
דורש גם `--apply`, ומבצע commit רק לאחר שכל בקשות המחיקה הצליחו.
**ה־commit כולל את כל השינויים הממתינים במכשיר, גם שינויים שלא ביצע הכלי.**
ב־Panorama מדובר ב־commit ל־Panorama; אין כאן פעולת push לפיירוולים המנוהלים.

`--delete-all` מוסיף לתוכנית את כל החוקים ב־rulebase, ב־pre-rulebase וב־post-rulebase
של האזור שנבחר. הוא עדיין מכבד KEEP ותלויות מחוץ לאזור, ולכן אינו מבטיח
מחיקת כל האובייקטים. מומלץ לבדוק את התוכנית במעבדה לפני שימוש במצב זה.

## התנהגות ומגבלות

- אובייקט מזוהה לפי סוג ושם. כתובת ושירות עם אותו שם אינם דורסים זה את זה.
- רק הפניות מחוקים שמיועדים למחיקה מתבטלות בניתוח. הפניות מחוקים אחרים נשמרות.
- אובייקטים נמחקים בשכבות: קבוצה לפני האובייקטים שאליהם היא מפנה.
- הפניות לא מוכרות והפניות מאזורים אחרים מטופלות באופן שמרני. אין כאן פתרון
  מלא של כללי ירושה ודריסה ב־Panorama, וייתכן שאובייקטים מיותרים יישארו.
- כל עוד נשארת קבוצה דינמית, נשמרים כל מועמדי הכתובות וקבוצות הכתובות באזור.
  הכלי אינו שואל את המכשיר על חברות בזמן ריצה ואינו מנסה לפרש את כל שפת הפילטרים.
- מחזורי תלויות נשמרים. הפלט מציג מי מפנה לכל אובייקט שנשמר.
- כשל מחיקה עוצר את המשך הביצוע ומונע commit אוטומטי. מחיקות קודמות אינן
  מתבטלות אוטומטית, ובכשל תקשורת ייתכן שהבקשה האחרונה כבר בוצעה במכשיר.
- בדיקת השינוי לפני המחיקה אינה נעילת קונפיגורציה או טרנזקציה. אל תערוך את
  המכשיר במקביל לריצה. הגיבוי אינו כולל מנגנון שחזור אוטומטי.
- קובצי גיבוי ותוכניות חדשים אינם דורסים קבצים קיימים. הרשאות מצומצמות מוגדרות
  במערכות POSIX; ב־Windows יש להגן על התיקייה באמצעות הרשאות Windows.

## בדיקות

```bash
python -m unittest discover -s tests -v
```

הבדיקות כוללות נתוני XML סינתטיים ולקוחות API מדומים. הן אינן מתחברות למכשיר
ואינן מחליפות בדיקת שילוב במעבדת PAN-OS אמיתית. קובצי ה־CLI המקוריים נשארו
ללא שינוי, והם אינם מורצים אוטומטית.
